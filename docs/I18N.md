Documentación de internacionalización de IoCode SOLUTIONS Web.

## 1. Propósito

Este documento define cómo funciona la internacionalización del proyecto IoCode SOLUTIONS Web.

La web soporta tres idiomas:

```text
es → Español
en → Inglés
de → Alemán
```

El objetivo no es solo cambiar textos en cliente. La arquitectura usa rutas reales por idioma para mejorar SEO, claridad, indexación y mantenimiento.

## 2. Principio principal

La internacionalización se basa en rutas estáticas reales:

```text
/es/
/en/
/de/
```

Cada idioma tiene slugs localizados:

```text
/es/servicios/
/en/services/
/de/leistungen/
```

No se usa un sistema de traducción exclusivamente client-side con `localStorage` para el contenido principal, porque eso sería insuficiente para SEO internacional serio.

## 3. Archivos principales

La i18n se reparte en estos archivos:

```text
src/i18n/config.ts
src/i18n/routes.ts
src/i18n/ui.ts
src/data/pageContent.ts
src/data/projects.ts
src/data/skills.ts

```

| Archivo                                 | Responsabilidad                                              |
| --------------------------------------- | ------------------------------------------------------------ |
| `src/i18n/config.ts`                    | Define idiomas soportados y locale por defecto               |
| `src/i18n/routes.ts`                    | Define rutas, slugs traducidos y equivalencias entre idiomas |
| `src/i18n/ui.ts`                        | Textos cortos reutilizables de interfaz                      |
| `src/data/pageContent.ts`               | Contenido principal de páginas por idioma                    |
| `src/data/projects.ts`                  | Proyectos por idioma                                         |
| `src/data/skills.ts`                    | Habilidades por idioma                                       |
| `src/layouts/BaseLayout.astro`          | Aplica `lang`, `canonical`, `hreflang` y metadatos           |

## 5. Idiomas soportados

Los idiomas soportados deben estar definidos en:

```text
src/i18n/config.ts
```

Ejemplo esperado:

```ts
export type Locale = "es" | "en" | "de";

export const locales: Locale[] = ["es", "en", "de"];

export const defaultLocale: Locale = "es";

export const localeNames: Record<Locale, string> = {
  es: "Español",
  en: "English",
  de: "Deutsch"
};
```

Regla: no añadir un idioma nuevo solo en una página. Todo idioma nuevo debe añadirse de forma consistente en configuración, rutas, contenido, navegación, sitemap y QA.

## 6. Modelo de rutas

Las rutas se definen desde:

```text
src/i18n/routes.ts
```

La pieza central es:

```text
routeAlternates
```

Este objeto define para cada página:

* clave interna;
* label de navegación por idioma;
* slug por idioma;
* path completo por idioma.

Ejemplo:

```ts
services: {
  key: "services",
  label: {
    es: "Servicios",
    en: "Services",
    de: "Leistungen"
  },
  slug: {
    es: "servicios",
    en: "services",
    de: "leistungen"
  },
  path: {
    es: "/es/servicios/",
    en: "/en/services/",
    de: "/de/leistungen/"
  }
}
```

## 7. Por qué existe `routeAlternates`

No basta con reemplazar el prefijo de idioma.

Incorrecto:

```text
/es/servicios/
→ /en/servicios/
```

Correcto:

```text
/es/servicios/
→ /en/services/
```

Los slugs están traducidos. Por eso el selector de idioma, el sitemap, el canonical y los hreflang deben usar una tabla central de equivalencias.

## 9. Tipos principales

`RouteKey` debe representar páginas, no idiomas.

Ejemplo:

```ts
export type RouteKey =
  | "home"
  | "services"
  | "plc"
  | "robotics"
  | "projects"
  | "skills"
  | "process"
  | "contact";
```

`Locale` debe representar idiomas.

Ejemplo:

```ts
export type Locale = "es" | "en" | "de";
```

## 10. Funciones esperadas en `routes.ts`

`src/i18n/routes.ts` debe exponer funciones equivalentes a:

```ts
export function getLocalizedPath(routeKey: RouteKey, locale: Locale): string {
  return routeAlternates[routeKey].path[locale];
}

export function getAlternatePaths(routeKey: RouteKey): Record<Locale, string> {
  return routeAlternates[routeKey].path;
}

export function getStaticRouteParams() {
  return Object.values(routeAlternates).flatMap((route) =>
    (["es", "en", "de"] as Locale[]).map((locale) => ({
      params: {
        locale,
        slug: route.slug[locale]
      },
      props: {
        locale,
        routeKey: route.key
      }
    }))
  );
}
```

Estas funciones permiten:

* generar páginas estáticas;
* construir navegación;
* construir canonical;
* construir hreflang;
* construir selector de idioma;
* construir sitemap.

## 11. Generación de páginas

La página dinámica principal vive en:

```text
src/pages/[locale]/[...slug].astro
```

Esta página debe usar:

```ts
export function getStaticPaths() {
  return getStaticRouteParams();
}
```

Eso permite que Astro genere las rutas estáticas de todos los idiomas.

La página debe recibir:

```ts
const { locale, routeKey } = Astro.props;
```

y cargar contenido desde:

```ts
pageContent[locale][routeKey]
```

## 12. Página home y slug `undefined`

La home no tiene slug específico.

Ejemplo:

```ts
home: {
  slug: {
    es: undefined,
    en: undefined,
    de: undefined
  },
  path: {
    es: "/es/",
    en: "/en/",
    de: "/de/"
  }
}
```

Esto permite que `[...slug].astro` genere correctamente:

```text
/es/
/en/
/de/
```

## 13. Layout y metadatos SEO

El layout principal vive en:

```text
src/layouts/BaseLayout.astro
```

Debe recibir:

```ts
type Props = {
  locale: Locale;
  routeKey: RouteKey;
  title: string;
  description: string;
};
```

Debe aplicar:

```astro
<html lang={locale}>
```

Debe generar canonical:

```astro
<link rel="canonical" href={canonicalUrl} />
```

Debe generar alternates:

```astro
<link rel="alternate" hreflang="es" href={`${siteConfig.url}${alternatePaths.es}`} />
<link rel="alternate" hreflang="en" href={`${siteConfig.url}${alternatePaths.en}`} />
<link rel="alternate" hreflang="de" href={`${siteConfig.url}${alternatePaths.de}`} />
<link rel="alternate" hreflang="x-default" href={`${siteConfig.url}${alternatePaths.es}`} />
```

Regla: no escribir `hreflang` manualmente en cada página.

## 14. Canonical

Cada página debe tener canonical apuntando a su propia versión idiomática.

Ejemplos:

```text
/es/servicios/ → canonical /es/servicios/
/en/services/ → canonical /en/services/
/de/leistungen/ → canonical /de/leistungen/
```

El canonical se calcula con:

```ts
getLocalizedPath(routeKey, locale)
```

## 15. Hreflang

Cada página debe declarar sus equivalentes idiomáticos.

Ejemplo para `services`:

```text
hreflang es → /es/servicios/
hreflang en → /en/services/
hreflang de → /de/leistungen/
x-default   → /es/servicios/
```

La fuente de verdad debe ser:

```ts
getAlternatePaths(routeKey)
```

## 16. Selector de idioma

El componente vive en:

```text
src/components/LanguageSwitcher.astro
```

Debe recibir:

```ts
type Props = {
  locale: Locale;
  activeKey: RouteKey;
};
```

Debe usar:

```ts
const paths = getAlternatePaths(activeKey);
```

Ejemplo:

```astro
<a class:list={{ "is-active": locale === "es" }} href={paths.es} hreflang="es" lang="es">ES</a>
<a class:list={{ "is-active": locale === "en" }} href={paths.en} hreflang="en" lang="en">EN</a>
<a class:list={{ "is-active": locale === "de" }} href={paths.de} hreflang="de" lang="de">DE</a>
```

No debe usar regex para reemplazar rutas.

Incorrecto:

```ts
Astro.url.pathname.replace("/es/", "/en/")
```

Correcto:

```ts
getAlternatePaths(activeKey)
```

## 17. Navegación

La navegación debe usar rutas localizadas.

Archivos implicados:

```text
src/i18n/routes.ts
src/data/navigation.ts
src/components/Navigation.astro
```

La navegación debe:

* mostrar labels localizados;
* enlazar a paths localizados;
* marcar la página activa por `RouteKey`;
* no duplicarse página por página.

Ejemplo conceptual:

```ts
navigationRouteKeys.map((routeKey) => {
  const route = routeAlternates[routeKey];

  return {
    key: route.key,
    href: route.path,
    label: route.label
  };
});
```

## 18. Contenido de páginas

El contenido principal vive en:

```text
src/data/pageContent.ts
```

Debe estar organizado por idioma y ruta:

```ts
pageContent[locale][routeKey]
```

Cada entrada debe incluir:

```ts
{
  title: string;
  description: string;
  eyebrow: string;
  heading: string;
  intro: string;
  cards?: Card[];
}
```

Regla: no dejar idiomas incompletos. Si falta contenido en `en` o `de`, la build puede pasar, pero el producto no debe considerarse listo.

## 22. Sitemap

El sitemap vive en:

```text
src/pages/sitemap.xml.ts
```

Debe generarse desde:

```ts
routeAlternates
```

No mantener un sitemap manual si las rutas están centralizadas.

Validación:

```powershell
(Invoke-WebRequest "http://localhost:8080/sitemap.xml" -UseBasicParsing).StatusCode
```

Resultado esperado:

```text
200
```

El sitemap debe incluir todas las rutas públicas indexables.

## 23. Robots.txt

El archivo vive en:

```text
public/robots.txt
```

Debe permitir indexación salvo decisión explícita.

Ejemplo recomendado para entorno público:

```txt
User-agent: *
Allow: /

Sitemap: https://iocode-solutions.com/sitemap.xml
```

Si el dominio cambia, actualizar `siteConfig.url` y `robots.txt`.

## 24. `siteConfig.url`

El dominio base vive en:

```text
src/data/site.ts
```

Ejemplo:

```ts
export const siteConfig = {
  url: "https://iocode-solutions.com"
};
```

Este valor afecta:

* canonical;
* hreflang;
* sitemap;
* Open Graph.

Antes de publicar, confirmar que el dominio es correcto.

## 25. Añadir una nueva página

Pasos obligatorios:

1. Añadir nueva clave a `RouteKey` en `src/i18n/routes.ts`.
2. Añadir entrada en `routeAlternates`.
3. Añadir `label` para `es`, `en`, `de`.
4. Añadir `slug` para `es`, `en`, `de`.
5. Añadir `path` para `es`, `en`, `de`.
6. Añadir contenido en `src/data/pageContent.ts`.
7. Añadir textos UI en `src/i18n/ui.ts` si aplica.
8. Añadir entrada en navegación si debe aparecer en menú.
9. Validar `npm run check`.
10. Validar `npm run build`.
11. Validar sitemap.
12. Validar selector de idioma.
13. Actualizar `QA_CHECKLIST.md` si la página añade un flujo nuevo.

No crear una página solo en un idioma.

## 26. Añadir un nuevo idioma

Pasos obligatorios:

1. Añadir el locale en `src/i18n/config.ts`.
2. Añadir nombre en `localeNames`.
3. Añadir rutas en `routeAlternates`.
4. Añadir labels de navegación.
5. Añadir contenido en `pageContent`.
6. Añadir textos UI en `ui`.
7. Añadir proyectos.
8. Añadir habilidades.
9. Actualizar `BaseLayout.astro` si hay textos comunes.
10. Actualizar `LanguageSwitcher.astro`.
11. Actualizar `sitemap.xml.ts` si el código no itera dinámicamente todos los locales.
12. Actualizar QA.
13. Revisar traducciones profesionalmente.

No añadir idioma nuevo si no hay contenido completo.

## 27. Cambiar un slug existente

Cambiar un slug es una decisión SEO sensible.

Pasos:

1. Cambiar slug en `routeAlternates`.
2. Cambiar path correspondiente.
3. Ejecutar build.
4. Revisar sitemap.
5. Revisar canonical.
6. Revisar hreflang.
7. Revisar navegación.
8. Revisar selector de idioma.
9. Si la web ya estaba publicada, crear redirección desde la URL antigua.
10. Documentar el cambio.

No cambiar slugs publicados sin plan de redirección.

## 32. Traducciones

Las traducciones deben ser profesionales y no literales cuando el texto técnico lo requiera.

Revisión mínima:

* español: revisión ortográfica y tono profesional;
* inglés: revisión técnica;
* alemán: revisión técnica, idealmente por hablante competente.

No marcar el proyecto como listo para uso comercial internacional si las traducciones no han sido revisadas.

## 33. Reglas de tono por idioma

### Español

* claro;
* profesional;
* técnico sin exageración;
* orientado a servicios.

### Inglés

* directo;
* técnico;
* no traducir literalmente expresiones españolas;
* evitar promesas excesivas.

### Alemán

* formal;
* claro;
* evitar frases demasiado largas;
* validar términos industriales como `SPS`, `Industrierobotik`, `Automatisierung`.

## 34. Formulario de contacto en i18n

El formulario debe mostrar labels localizados.

Textos que deben existir en `ui.ts` o equivalente:

* nombre;
* correo;
* tipo de proyecto;
* mensaje;
* preparar correo;
* aviso de datos sensibles;
* LinkedIn;
* GitHub;
* email.

El formulario sigue siendo `mailto:` en todos los idiomas.

No traducirlo como si enviara datos a servidor.

## 35. Errores comunes

### Error: selector genera `/en/servicios/`

Causa: se está reemplazando solo el prefijo del idioma.

Solución: usar `getAlternatePaths(activeKey)`.

### Error: página existe en español pero no en inglés

Causa: contenido incompleto o ruta no añadida en `routeAlternates`.

Solución: añadir entrada completa para todos los idiomas.

### Error: sitemap no incluye una ruta

Causa: sitemap manual o ruta ausente de `routeAlternates`.

Solución: generar sitemap desde `routeAlternates`.

### Error: canonical apunta a español en todas las páginas

Causa: canonical hardcodeado.

Solución: usar `getLocalizedPath(routeKey, locale)`.

### Error: `hreflang` incorrecto

Causa: rutas equivalentes manuales o incompletas.

Solución: usar `getAlternatePaths(routeKey)`.

## 36. No-go conditions i18n

No publicar si ocurre cualquiera:

* falta un idioma en una página pública;
* el selector de idioma lleva a slug incorrecto;
* canonical incorrecto;
* hreflang incorrecto;
* sitemap incompleto;
* `html lang` incorrecto;
* contenido mezclado sin intención;
* traducciones incompletas;
* `/en/servicios/`, `/de/servicios/` o rutas mixtas similares existen como resultado del selector;
* slugs publicados se cambian sin redirección;
* se usa solo JavaScript cliente para traducir contenido principal;
* no se ha revisado el contenido alemán e inglés para publicación comercial.

## 39. Resumen

La internacionalización del proyecto se basa en:

```text
rutas reales + slugs traducidos + routeAlternates + canonical + hreflang + sitemap
```

Esta decisión evita las limitaciones de una traducción solo client-side y prepara la web para SEO internacional.

La fuente de verdad de rutas es:

```text
src/i18n/routes.ts
```

La fuente de verdad de contenido es:

```text
src/data/pageContent.ts
src/data/projects.ts
src/data/skills.ts
src/i18n/ui.ts
```

No se debe publicar la web como multidioma lista si las rutas, metadatos, selector y traducciones no han pasado QA.
