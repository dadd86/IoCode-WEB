## Alcance y fuentes de verdad

El sitio publica páginas estáticas reales para `es`, `en` y `de`. No cambia textos
solo en el cliente. Las fuentes de verdad son:

- `src/i18n/config.ts`: `Locale`, locales soportados y locale por defecto.
- `src/i18n/routes.ts`: claves, slugs, paths, navegación y parámetros estáticos.
- `src/i18n/ui.ts`: textos breves reutilizables.
- `src/data/pageContent.ts`: contenido principal localizado.
- `src/data/projects.ts` y `src/data/skills.ts`: contenido de proyectos y habilidades.
- `src/pages/[locale]/[[...slug]].astro`: generación de rutas.

La versión explicativa anterior se conserva en
[`archive/I18N.full-2026-07-28.md`](archive/I18N.full-2026-07-28.md). Este
documento es el contrato operativo vigente.

## Contrato de rutas

`RouteKey` identifica una página, nunca un idioma. Cada clave de
`routeAlternates` debe contener, para los tres locales:

- `label`: etiqueta de navegación;
- `slug`: segmento localizado, o `undefined` solo para `home`;
- `path`: ruta absoluta con prefijo de idioma y barra final.

```ts
type RouteKey =
  | "home"
  | "services"
  | "plc"
  | "robotics"
  | "about"
  | "projects"
  | "skills"
  | "process"
  | "contact";

type LocalizedRoute = {
  key: RouteKey;
  label: Record<Locale, string>;
  slug: Record<Locale, string | undefined>;
  path: Record<Locale, string>;
};
```

`navigationRouteKeys` define el orden del menú. `getLocalizedPath()` y
`getAlternatePaths()` deben leer la tabla central; no se construyen equivalencias
sustituyendo prefijos. `getStaticRouteParams()` debe producir una combinación por
`RouteKey` y locale para que Astro genere todas las rutas.

### Matriz vigente

| Clave | ES | EN | DE |
|---|---|---|---|
| `home` | `/es/` | `/en/` | `/de/` |
| `services` | `/es/servicios/` | `/en/services/` | `/de/leistungen/` |
| `plc` | `/es/automatizacion-plc/` | `/en/plc-automation/` | `/de/sps-automatisierung/` |
| `robotics` | `/es/robotica-industrial/` | `/en/industrial-robotics/` | `/de/industrierobotik/` |
| `about` | `/es/empresa/` | `/en/company/` | `/de/unternehmen/` |
| `projects` | `/es/proyectos/` | `/en/projects/` | `/de/projekte/` |
| `skills` | `/es/habilidades/` | `/en/skills/` | `/de/faehigkeiten/` |
| `process` | `/es/proceso/` | `/en/process/` | `/de/prozess/` |
| `contact` | `/es/contacto/` | `/en/contact/` | `/de/kontakt/` |

Canonical, `hreflang`, selector de idioma, navegación y sitemap deben derivarse de
esta matriz. Si una ruta publicada cambia de slug, requiere redirección desde la
URL anterior antes del despliegue.

## Procedimiento de alta de una página en ES, EN y DE

Una página no se considera dada de alta si falta cualquiera de estos pasos:

1. Añadir la clave a `RouteKey` en `src/i18n/routes.ts`.
2. Añadir a `routeAlternates` el `label`, `slug` y `path` de `es`, `en` y `de`.
3. Añadir la clave a `navigationRouteKeys` si pertenece al menú.
4. Crear en `src/data/pageContent.ts` el contenido completo de los tres locales.
5. Añadir las claves compartidas necesarias a `src/i18n/ui.ts` en los tres idiomas.
6. Confirmar que `getStaticRouteParams()` genera las tres rutas.
7. Confirmar canonical, alternates `hreflang` y entrada de sitemap.
8. Probar desde cada variante que el selector llega a las otras dos equivalentes.
9. Ejecutar los gates indicados al final de este documento.

No se publica una página disponible en un solo idioma ni se usa el texto español
como fallback silencioso para EN o DE.

## Plantilla de clave localizada

Usar esta forma al ampliar una tabla de contenido:

```ts
type LocalizedValue<T> = Record<Locale, T>;

export const exampleKey: LocalizedValue<string> = {
  es: "Texto revisado en español",
  en: "Reviewed English copy",
  de: "Geprüfter deutscher Text"
};
```

Para una ruta:

```ts
example: {
  key: "example",
  label: { es: "Ejemplo", en: "Example", de: "Beispiel" },
  slug: { es: "ejemplo", en: "example", de: "beispiel" },
  path: { es: "/es/ejemplo/", en: "/en/example/", de: "/de/beispiel/" }
}
```

La clave nueva debe añadirse también al tipo `RouteKey`. No se aceptan claves
sueltas ni `as any` para eludir el contrato.

## Reglas de contenido y SEO

- Mantener el mismo significado, alcance técnico y nivel de evidencia en los tres
  idiomas; la traducción puede ser idiomática, pero no ampliar claims.
- No mezclar idiomas dentro de una variante.
- Traducir títulos, descripciones, navegación, mensajes de formulario y textos de
  accesibilidad.
- Mantener canonical autoconsistente y alternates completos para ES, EN y DE.
- Usar `x-default` solo con la decisión central ya implementada; no improvisarlo
  por página.
- No cambiar un slug publicado sin redirección y prueba de enlaces.

## Criterio de cierre

El cambio queda cerrado cuando:

- existen ruta y contenido completo en ES, EN y DE;
- menú, selector, canonical, `hreflang` y sitemap usan `routeAlternates`;
- no hay claves ni locales incompletos;
- las tres variantes responden y enlazan entre sí;
- pasan los comandos existentes:

```text
npm run check
npm run typecheck:src
npm run build
npm run docs:lint
```

El número de líneas es un indicador de mantenibilidad, no sustituye estos
criterios.
